# Append-only checkpoint floor: prototype evidence boundary

`JournalFingerprintFloors` stores relationship-scoped revision and fingerprint records as checksummed newline-delimited JSON. Each operation acquires an exclusive sidecar lock using O_EXCL, replays the complete journal, and refuses malformed/truncated records. Commits append and sync before returning success. Tests model reopening, scope separation, stale revision and same-revision fork rejection, held locks, and truncated journal rejection.

**Not a production authorization backend.** A stale lock after a crash blocks access indefinitely; the implementation intentionally never breaks it. The lock file is removed after ordinary process exit, and there is no authenticated owner or stale-lock recovery. The journal has no external anti-rollback anchor: an attacker able to restore an older complete journal can roll back revocation state. Parent-directory and filesystem ACL ownership, symlinks/reparse points, malicious local writers, directory durability, power loss, and cross-process Windows/Linux contention are not qualified. A checksum detects corruption, not malicious edits. A failed/partial append may permanently poison the journal, deliberately failing closed.

Do not wire this prototype into real authorization or mounting. Before qualification, establish protected storage-root ownership and path confinement, OS-specific durable synchronization and locking, safe crash recovery, anti-rollback anchoring, authenticated pairing/provisioning, per-read revocation, independent hostile review, and exact-head Windows/Linux CI and host fault-injection evidence. No real drives or tailnet policies are modified by this change.
