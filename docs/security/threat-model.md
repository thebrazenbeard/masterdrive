# MasterDrive threat model (v0.1, source-first)

Status: **design and source review; not a runtime security qualification**. Updated 2026-11-02 UTC. Review target: the initial private-mesh, read-only federation prototype, including the controller, explicit host catalog, exported-root agent, and browser UI. Source inspected in isolated local copies of `internal/server`, `internal/agent`, `internal/catalog`, and `cmd/masterdrive`; those copies are not cryptographically tied to a published PR head. Revalidate every finding against the final integrated commit.

## Product boundary

MasterDrive's first release is a *virtual namespace*, not a distributed disk or RAID. It presents opt-in shares from distinct Windows/Linux hosts in one GUI and fetches bytes from the original host. A disconnected host means its files are unavailable; a displayed total of free bytes is **not** a single writable capacity budget. No automatic device enumeration may silently export a drive or path. No replication, placement, consistency, failover, or recoverability claim is established by a working browser.

Tailscale describes an existing alpha feature, **Taildrive**, that already shares folders between Windows/Linux and other devices via a tailnet and WebDAV. This is direct prior art, not a security property MasterDrive inherits ([Taildrive](https://tailscale.com/docs/features/taildrive)). The differentiator must be measured against it. MasterDrive must use a private-mesh route with its *own* per-share authorization; Tailscale reachability or tailnet membership does not automatically grant read rights.

## Actors, assets, and trust boundaries

| Component | Assets it can reach | Who controls it / trust issue |
| --- | --- | --- |
| Host owner | Local filesystem and explicit share configuration | Only an intentional opt-in may expose a root |
| Agent process | Files beneath its opened export roots; bearer secret | Network input, file names, symlinks/reparse points and concurrent filesystem mutation are untrusted |
| Controller | Host registry, peer credentials, local session, outbound proxy | A local browser is not trusted merely because it can connect to loopback; registered endpoints require validation |
| GUI/browser | File names, metadata, session cookie, downloads | Filenames are untrusted display input; browser extensions, unrelated sites and DNS rebinding are adversarial possibilities |
| Private mesh | Encrypted routing, peer/network identities | Mesh access controls are distinct from application share ACLs; identity cannot be inferred solely from an IP address |
| Remote peer / compromised machine | Metadata, file stream, HTTP response headers | May send malicious JSON, redirects, invalid ranges, oversized responses, partial transfers, or fabricated labels |

Assets: private file contents and names; machine-local share paths; peer tokens and controller session; registry integrity; host identity; disk/device availability. Desired invariants: no access outside explicit roots, no unauthorized listing/download, no secret in browser-visible API or logs, fail-closed offline/invalid peers, no default export, no remote plaintext or public listener, no silent write or deletion.

## Severity-ranked attack paths

| ID | Risk / credible attack | Severity | Required control and evidence |
| --- | --- | --- | --- |
| MD-01 | **Directory escape** through `..`, URL-decoding layers, absolute/UNC/device names, symlinks, Windows junctions/reparse points, or time-of-check/time-of-use races | **Critical** if exposed | Open with a pinned, traversal-resistant directory handle (`os.Root`), reject malformed path syntax, serve regular files only, test Windows and Linux live link swaps. `filepath.Clean` + `EvalSymlinks` + `os.Open` is not an adequate race defense. [Go os.Root](https://go.dev/blog/osroot), [Windows reparse points](https://learn.microsoft.com/en-us/windows/win32/fileio/reparse-points) |
| MD-02 | Unpatched Go `os.Root` path escape with final symlink followed by `/` on Unix | **High** | Pin patched toolchains: **Go 1.25.12+, Go 1.26.5+, or Go 1.27 release after rc.2**, as applicable. Test a trailing-slash symlink escape; do not equate a `go.mod` version string with the compiler running CI/binaries. [GO-2026-4970 / CVE-2026-39822](https://pkg.go.dev/vuln/GO-2026-4970) |
| MD-03 | Readable export contains Unix bind mount, `/proc`, device/special file, network mount, Windows reparse target, or nested sensitive path intentionally/unintentionally mounted underneath | **High** | `os.Root` does **not** confine to one filesystem or reject Unix devices and bind mounts. Restrict downloads to regular files, document nested mounts, and add optional mount-boundary policy before broad deployment. Review all child directories of a chosen root. [Go os.Root documentation](https://pkg.go.dev/os#Root) |
| MD-04 | Remote access granted merely by joining tailnet, knowing service URL, or presenting a spoofed Tailscale identity header | **Critical** if public/remote | Require independent per-peer and per-share authorization, explicit pairing, revocation, and authenticated transport. If using Tailscale Serve identity or app-capability headers, accept them **only from a localhost-bound backend behind Serve**, never directly from arbitrary HTTP clients. [Tailscale Serve](https://tailscale.com/docs/features/tailscale-serve), [Grants](https://tailscale.com/docs/features/access-control/grants) |
| MD-05 | Unencrypted remote HTTP, invalid TLS hostname, public bind, unexpected `tailscale funnel`, browser DNS rebinding | **High** | Agent and controller default to loopback. Remote access through explicitly configured authenticated encrypted mesh/HTTPS. Reject plain remote HTTP and invalid certificates; require Host allowlist for local controller; verify Serve, **not Funnel**, is in effect. [Tailscale security](https://tailscale.com/docs/reference/best-practices/security), [Serve](https://tailscale.com/docs/reference/tailscale-cli/serve) |
| MD-06 | Browser can call local file gateway without a local operator session; hostile page triggers cross-origin request or file download | **High** | Ephemeral local session independent of peer tokens, HttpOnly SameSite cookie, no CORS wildcard, non-GET session activation requires unguessable secret, origin/host checks, no API mutations in GET. Test `Origin: https://attacker.test`, missing/foreign cookie, malicious Host. [OWASP CSRF](https://cheatsheetseries.owasp.org/cheatsheets/Cross-Site_Request_Forgery_Prevention_Cheat_Sheet.html) |
| MD-07 | Browser XSS from remote file names, labels, share metadata; filename/header injection on download | **High** | Render via `textContent` (never untrusted `innerHTML`), use structured URL construction, sanitize `Content-Disposition`, use `attachment` and `nosniff`, do not embed file HTML previews without sandbox. [OWASP XSS](https://cheatsheetseries.owasp.org/cheatsheets/Cross_Site_Scripting_Prevention_Cheat_Sheet.html), [Content-Disposition](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Content-Disposition) |
| MD-08 | Gateway SSRF or credential leak through arbitrary URL, redirect, proxy, DNS rebinding or user-info in host URL | **High** for network-exposed registration | Host registration must remain an explicit local privileged act; URL syntax origin-only, no user-info/query/path fragments; only HTTPS remote; disable redirects; bound outbound dial/response times; never forward secrets to arbitrary redirects. Domain/IP allowlisting and resolution pinning become mandatory if untrusted users can register. [OWASP SSRF](https://cheatsheetseries.owasp.org/cheatsheets/Server_Side_Request_Forgery_Prevention_Cheat_Sheet.html) |
| MD-09 | Modified file across ranged transfers yields corrupt reconstructed download; upstream claims wrong length or stalls midstream | **Medium** in read-only prototype; **High** if used as backup | Validate requested vs returned byte ranges and body length; terminate incomplete stream; implement strong entity validator (`ETag`/hash and `If-Range`) or disable resumable downloads until consistent. A `Content-Length` match does not prove content integrity. |
| MD-10 | Controller and CLI edit separate registry snapshots, losing updates or showing stale host state | **Medium** | Use locking or one authoritative local service with mutation API. At minimum require explicit controller restart after add/remove and reject concurrent writers. Test two processes interleaving updates and recovery after interrupted atomic replace. |
| MD-11 | Revocation is cosmetic: catalog removal leaves peer token valid, old sessions retained, agent still serving root | **High** | Separate `unregister` from **revoke**; revoke at the agent, rotate token/credential, remove ACL/grant, and confirm old token fails. An agent stopping and closing roots must be observed; offline peer revocation is pending, not completed. |
| MD-12 | Large directories, malformed JSON, zip-bomb-like metadata, slow downloads, file descriptors retained, slowloris and resource exhaustion | **Medium** | Bound list pagination, peer response size, headers, concurrency, deadlines, download bandwidth or sessions; cancellation must close handles. Test over-limit and unresponsive peers; do not block all hosts when one host stalls. |
| MD-13 | Path or token leaks through access logs, browser URL/query, analytics, error traces, crash dumps, GUI local storage | **High** | Tokens never in URLs or registry JSON/browser APIs. Session bootstrap fragments must be consumed and removed from history; logs should redact bearer/session and physical share paths. Use file permissions/OS secret store as credential scope expands. |
| MD-14 | Confusing virtual namespace with real pooled disk causes destructive expectations (automatic placement, redundancy, writes) | **High** product integrity | Label this release **read-only federation**, with per-host ownership and offline state. No “single drive”, “RAID”, “backup”, “high availability”, capacity aggregation, or lossless migration claims without direct end-to-end proof. |

## Findings from local source inspection (not final-head proof)

- **Observed protection:** The agent source uses `os.OpenRoot`, pins root handles, validates `fs.ValidPath` and `filepath.Localize`, checks regular files before download, and requires a bearer token for all endpoints. It rejects automatic exports and restricts page sizes. The controller binds loopback, checks Host, performs explicit registration, avoids redirects, enforces body limits, and attempts to validate range responses. These are source-level observations, not test results from Windows, Linux, or a live tailnet.
- **Observed partial:** Controller session code uses an ephemeral fragment bootstrap followed by an `HttpOnly`, `SameSite=Strict` cookie. Confirm the final UI actually consumes and clears fragments and never reveals the session token. `Secure` is absent because current controller is local HTTP; if promoted behind HTTPS without adjustment, upgrade cookie policy.
- **Observed gap:** The catalog explicitly loads into process memory and says concurrent processes must not write the same directory. `add-host`/`remove-host` in separate CLI processes cannot refresh an already-running controller; concurrent CLI edits can overwrite one another. Not a data-loss of exported files, but a real management consistency defect.
- **Observed gap:** No verified tailnet peer identity binding, grant-derived share permission, pairing handshake, or live revoke protocol is present in the reviewed source. A manually entered HTTPS URL plus bearer token is a prototype security model; it does **not** qualify the user-facing claim “Tailscale but for hard drives.”
- **Observed gap:** Ranged downloads have numerical range/body checks but no stable file version/hash enforcement across separate ranges. Whole-file transfers cannot detect same-length remote corruption without a hash or end-to-end comparison.

## Release decision

**Design survives for an explicitly labeled read-only, single-operator, private-mesh prototype** only if MD-01/02/04/05/06/07/08 security tests pass on exact integrated code and binaries. **Production cross-host sharing remains unqualified** until identity, pairing/revoke, patched builds, per-share policy, actual Tailscale/WireGuard traffic, and Windows/Linux path-confinement evidence exist. No claims of an actual distributed filesystem are justified.
